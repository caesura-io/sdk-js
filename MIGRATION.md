# Migration guide

Package versions and changelogs are generated by Changesets.

## Migrating to core/OpenAI 0.5.0 and AI SDK 0.6.0

These changes apply when upgrading from core/OpenAI 0.4.0 and AI SDK 0.5.0.

### Handle conversation creation failures

`createConversation()` now returns `Promise<string | undefined>`. Under the default
`failurePolicy: 'continue'`, recoverable creation failures and dependency timeouts
are reported through error hooks and return `undefined`. Previously they rejected.
Check the result before saving or reusing it:

```ts
const conversationId = await client.createConversation({ name: 'Conversation' });
if (conversationId) await application.saveConversationId(conversationId);
await client.responses.create(
  { model: 'your-model', input: 'Hello' },
  { caesura: {
    ...(conversationId ? { conversationId } : { stateless: true }),
    turn: { id: 'customer-message-1', origin: 'customer' },
  } },
);
```

Use `failurePolicy: 'throw'` when creation must succeed. Caller cancellation,
expired caller deadlines, invalid configuration and unsupported capabilities still
reject. Successful creation returns the real ID; no ID is invented on failure.

`stateless: true` explicitly permits a call without a conversation ID. Hooks must
handle an absent `correlation.conversationId` for these calls. Stateful calls still
require an ID, including with `persist: false`.

### Saving and fallback

`persist: true` now saves new customer messages and completed agent replies,
including customer turns skipped by analysis cadence. Use `recordMessages` for
application-provided greetings; recording a message does not trigger analysis.
`persist: false` disables hosted saving. Application storage hooks remain separate.

Under `continue`, failed hosted customer-message storage permits stateless analysis
for that invocation. Failed analysis permits generation without new guidance;
failed reply storage does not withhold the reply. Strict policy and required
application hooks retain their contracts. Dependency timeouts follow failure
policy; caller cancellation and deadlines still stop the invocation.

Fallback respects `mode`. Use `sync` for guidance in the current response. ID-free
background results are available through completion hooks and `flush()`, but are
not reused by later calls. Calls with an existing ID retain their guidance state.

Reuse stable message IDs and retain durable SDK state to recognize retries across
restarts. Retries must preserve text and speaker index. Failed writes are not
replayed automatically; retry storage with the same ID. See
[conversations and persistence](docs/conversations.md) for the full contract.

## Migrating to core/OpenAI 0.4.0 and AI SDK 0.5.0

The following describes the earlier upgrade from core/OpenAI 0.3.0 and AI SDK
0.4.0. For 0.5.0 / 0.6.0, also apply the creation, fallback, and transcript-saving changes above.

### Conversations and sessions

The default `baseUrl` is `https://api.caesurao.com`; most applications can omit it.

All stateful calls now require `conversationId`, even with `persist: false`. Missing
IDs raise `CaesuraError` with kind `configuration` before analysis or model work,
regardless of failure policy. No shared `"default"` fallback remains.

Remove `autoCreateConversation` entirely (even `false` is rejected). Remove
`backendConversationId` from custom state. If migrating an existing mapping, recover
and save its **backend ID** before discarding the mapping; move retained guidance
state under that ID. Do not reuse the old local label as if it were a backend ID.

```ts
// Before: autoCreateConversation: true, per-call conversationId: localSessionKey
const client = createCaesura(openai, { apiKey: process.env.CAESURA_API_KEY });
// Only when the application intentionally starts a NEW conversation:
const conversationId = await client.createConversation({
  name: 'Conversation',
});
await application.saveConversationId(conversationId);
// Subsequent calls load that saved ID, never create merely because cache is empty.
await client.responses.create(
  { model: 'your-model', input: 'Hello' },
  {
    caesura: {
      conversationId,
      turn: { id: 'customer-message-1', origin: 'customer' },
    },
  },
);
```

Core and AI SDK middleware expose the same creation method. Per-call IDs override
an optional immutable configured ID; a shared client has no current conversation.
Creation returns the authoritative opaque ID and emits `conversation-created`.

`clear(id)`, eviction and restart only affect SDK guidance/cadence state; they never
create, replace or delete the backend conversation. Supply history and restore an
async/sync persistent store yourself; an ID does not load historical messages.

Provider audit now emits `stream-start` and terminal `stream-end` (completed,
cancelled, failed, incomplete), with chunks retaining terminal usage and native error data.
A stream handle is not a completed `response`. SDK provenance is attached to audit
correlation, never provider parameters.

### Analysis values and public types

`CaesuraAnalysis` now represents any JSON value or plain text. Code that reads
`analysis.recommendation` must first narrow the value to an object and validate
the field. Unknown fields remain in their original location; no `extra` object is
created. Malformed responses advertised as JSON are errors.

```ts
function recommendation(analysis: CaesuraAnalysis): string | undefined {
  if (
    analysis !== null &&
    typeof analysis === 'object' &&
    !Array.isArray(analysis)
  ) {
    const value = analysis.recommendation;
    return typeof value === 'string' ? value : undefined;
  }
}
```

`{analysis}` renders the full value. `{analysis.next-step}` and
`{analysis.latest.speaker}` read those exact object keys, without nested lookup.
Zero and false are valid values. Boolean `isSame: true` suppresses new guidance
while preserving previous guidance; it does not suppress the dialogue request.
`keepLast: 0` injects no guidance and leaves stored history intact.

OpenAI's wrapped create methods retain streaming overloads and promise helpers.
The per-call `caesura` option belongs to the wrapped client, not the original
OpenAI client. Supported OpenAI versions are `>=4.87.3 <8`; AI SDK supports majors
5, 6, and 7. Node.js 22 or newer is required by this repository's build/validation.

### Shared text and budgeting policy

Text parts concatenate exactly, without inserted spaces or newlines. Supplied
whitespace is preserved. Only customer and agent text becomes dialogue context;
system instructions, tool results, and reasoning items do not.

`send.maxMessages` (default `10`) and `send.maxInputChars` apply to the complete
outbound analysis request, including previous analyses. Character limits count
Unicode code points, not UTF-16 units, bytes, or grapheme clusters. Emoji are not
split into surrogate halves; combining sequences may span multiple code points.

Newest dialogue has priority. The remaining character budget retains a suffix
of the oldest dialogue message that fits. Whole analyses use the remaining
message and character budget newest-first, stopping at the first that cannot
fit. Older, smaller guidance cannot replace newer guidance that exceeds the
budget. Structured analyses use compact Unicode-preserving JSON, and the budget
counts that actual serialized text. Zero limits skip analysis; negative limits
are rejected.

Occurrence anchors identify the original dialogue prefix, including participant
identity, before any SDK trimming. Retained occurrences keep their placements;
analyses whose anchors are missing collapse to the latest leading context entry
before history budgeting. Background work snapshots dialogue before waiting. These operations
do not alter caller-owned messages or original provider roles.

Keep the provider's normal `user` and `assistant` roles. Configure participant
labels with `speakerNames`; the SDK handles the analysis request format.

Reused SDK guidance is removed before collecting dialogue and reinjected only
while eligible. Messages carrying names, indices, audio, tool metadata, or
non-text content remain real provider messages. An anonymous text-only message
identical in role and text to guidance is inherently ambiguous after serialization;
retain a name or explicit index on real dialogue to distinguish it.

### Customer-turn lifecycle

See [stores, cancellation and auditing](docs/application-adapters.md).

- Pass `caesura: { turn: { id, origin: 'customer' }, dialogue? }` in OpenAI request
  options, or `providerOptions.caesura` for AI SDK. Reuse IDs on continuations and
  retries. Mark internal calls explicitly; use trusted dialogue selection for RAG.
- Cadence counts distinct customer events, not model invocations. Without metadata,
  the SDK only triggers on a final user message and uses its prefix occurrence ID.
- Custom stores must add `set(id, state)` and support JSON-serializable state.
  All store methods may return promises; stop relying on mutation of `get()` values.
  Read through `await engine.getState(id)` and use `await engine.updateState(id, update)`
  for coordinated writes. Await lifecycle methods such as `clear` and `shutdown`.
  Low-level code using `engine.client` must now narrow its optional type.
- Replace `store.get(id).inFlight` polling with `await client.caesura.flush(id)` or
  `await middleware.caesura.flush(id)`. Use engine clear/shutdown to cancel work.
- Choose `failurePolicy: 'throw'` with `mode: 'sync'` when analysis and awaited
  `persistAnalysis` must succeed before the Agent model call. Default is continue.
- Capture `onProviderEvent` or put external audit middleware inside Caesura so it
  observes the injected native request. Observational callbacks are not persistence.

### Provider-native copies and stream terminal evidence

URL-valued image/file content is preserved without `structuredClone(URL)` or JSON
serialization. Audit snapshots retain detached URL and binary values; audit storage
adapters should serialize those values deliberately.

`ProviderStreamStatus` adds `incomplete`. Update exhaustive switches on
`ProviderAuditEvent` stream-end status. Bare EOF is no longer `completed`: Chat needs
a finish reason for choice 0, Responses needs `response.completed`, and AI SDK needs
a `finish` part. Responses incomplete events also report `incomplete`. Unsuccessful
streams never create completed-agent transcript entries. Native chunks, errors and
late usage remain available. A valid finish reason such as `length` indicates protocol
termination and remains eligible for persistence; it does not guarantee semantic
completeness. Inspect `value.finishReason` for Chat and native terminal parts for the
other APIs when applying an application-specific policy.

SDK identity accompanies creation and analysis automatically; see the
[SDK diagnostics](docs/conversations.md#sdk-diagnostics).

### Required audit cancellation

`persistProviderRequest(event, context)` now supplies a separate
`ProviderAuditContext` with an `AbortSignal` and optional absolute `deadline`.
One-argument callbacks remain compatible. Pass these controls to your audit store
when it supports cooperative cancellation. Both streaming and non-streaming calls
stop waiting promptly when cancelled or when their explicit deadline expires,
without invoking the provider afterward. These outcomes reject even under the
continue policy; ordinary storage errors retain that policy's behavior.

Cancellation does not roll back audit writes or terminate synchronous blocking
work. See [the audit contract](docs/application-adapters.md#final-provider-audit).
